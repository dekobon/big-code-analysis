# Match arms rustfmt declines to format, per file.
# Maintained by check-rustfmt-bail.py; see AGENTS.md "Validation gates".
# Lower-or-equal current counts pass; any increase fails CI.
# Regenerate with: ./utils/check-rustfmt-bail.py --update
#
# An entry means rustfmt emitted that many match-arm headers verbatim,
# so everything in the enclosing `match` sits outside `cargo fmt
# --check`. There are two causes and this gate cannot tell them apart:
#
#   1. A comment inside a match *pattern* (between the pattern and its
#      `=>`, or between `|` alternatives). Fix by hoisting the comment
#      above the arm, outside the pattern — never by deleting it. See
#      .claude/rules/formatting.md.
#   2. A `macro_rules!` body rustfmt cannot parse, typically a
#      metavariable in a non-Rust position such as the pattern
#      repetition `$ternary $(| $short_circuit)+`. No comment is
#      involved; hoisting fixes nothing and the entry is permanent.
#   3. An arm wider than rustfmt's `max_width` of 100 columns. One
#      over-long arm header makes rustfmt emit the whole match
#      verbatim, with no comment and no macro in sight. Wrap or
#      shorten it; this is the cause you can act on immediately.
#
# Check which one you have (`./utils/check-rustfmt-bail.py --show FILE`
# names the stuck arms) before editing anything: an arm past 100
# columns is cause 3, an in-pattern comment is cause 1, and neither --
# inside a `macro_rules!` body -- is cause 2.
#
# ---- notes below are preserved across --update ----
# Known cause-2 entries, i.e. permanent — do not go looking for a
# comment to hoist in these:
#
#   enums/src/macros.rs        `Lang::$camel => stringify!($camel)`
#   src/macros/mod.rs          `mk_lang!` / `mk_action!` / `mk_langs!`
#                              bodies; every arm is `LANG::$camel => …`
#   src/metrics/cyclomatic.rs  `impl_cyclomatic_c_family!`, whose arm
#                              `… | $ternary $(| $short_circuit)+ =>`
#                              is a pattern repetition, not Rust
#   tests/common/mod.rs        an `insta::with_settings!` invocation,
#                              whose `key => value` token tree is not a
#                              match at all
#   src/vcs/error.rs           `classify_error_variants!` (#1245): its
#                              matcher, plus the 11 `$pat => $sample`
#                              entries at the invocation, which are
#                              `pattern => expression` pairs and so
#                              parse as neither. Deliberate: generating
#                              `is_client_input` and
#                              `client_input_samples` from one list is
#                              what makes a new client-input variant a
#                              compile error. Those 11 lines sit outside
#                              `cargo fmt` — keep them one per line and
#                              under 100 columns by hand.
#
# Every remaining entry is cause 1, and all of them share one shape:
# a section comment sitting between `|` alternatives of a single long
# or-pattern —
#
#     // Punctuation acting as operators
#     | LPAREN | LBRACE | COMMA
#     // Arithmetic
#     | PLUS | DASH | STAR => HalsteadType::Operator,
#
# Hoisting such a comment above the arm means splitting the arm, so
# each section keeps the rationale that names it. That is the readable
# form, and it is not available here: the split arms have identical
# bodies, which `clippy::match_same_arms` rejects — pedantic is
# `warn` workspace-wide and CI runs `-D warnings`. Measured on
# `src/getter/` (#1136): 17 modules split cleanly and reformatted with
# no metric change, and clippy then reported 28 errors, every one of
# them `match_same_arms` or `too_many_lines`.
#
# The alternative — stacking every section comment above the arm —
# detaches each from the tokens it names, which for a 40-line operator
# alphabet is worse than the bail.
#
# DECIDED (#1136, 2026-08-02): these entries stay. Do not open a
# campaign to clear them. The three candidate remedies were priced:
#
#   * `#[rustfmt::skip]` buys nothing measurable. Probed directly: a
#     bailing match reports the same count with and without it, because
#     the gate measures what rustfmt declined to reformat and the
#     attribute declines it too. It also cannot sit on the `match` —
#     attributes on expressions are unstable (E0658) — so it goes on
#     the enclosing `fn` and removes that whole function from `cargo
#     fmt`, which is less coverage than the bail it documents.
#   * Splitting plus `#[allow(clippy::match_same_arms)]` does restore
#     formatting, at the cost of an `allow` for a lint that is firing
#     correctly, and of the reflow dissolving the visual grouping the
#     sections exist to provide. `src/getter/python.rs` additionally
#     crosses its 50k halstead.effort limit when split.
#   * Stacking the comments needs no `allow` and loses the association
#     between each label and its tokens, which is the whole content.
#
# The problem #1136 was filed for was that these matches sat outside
# the formatting gate and nobody knew which ones. That is fixed by this
# gate, not by editing the tables: the set is enumerated, per-file,
# fail-on-increase. What remains is cosmetic, and every way of buying
# it makes these tables harder to read.
#
# A single-comment bail with nothing to split is still worth hoisting
# when you are in the file anyway — that is how the `Else /* else-if
# also */ =>` family across src/metrics/cognitive/ was cleared. Ratchet
# with `--update` in the same commit when you do.
#
# Watch the line length in every file listed here by hand. rustfmt is
# not checking it, and it does drift: before #1136 `src/getter/java.rs`
# carried a 252-character match arm.
